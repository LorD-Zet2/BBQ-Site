# BBQ в Махачкале — статический сайт для Vercel

Упрощённый Next.js-проект без базы данных, API, миграций и серверных секретов. Конструктор считает заказ в браузере и открывает WhatsApp или Telegram с готовым текстом. `next build` создаёт статическую папку `out/`.

Важно: Vercel Hobby стоит $0, но по [действующим правилам](https://vercel.com/docs/limits/fair-use-guidelines) предназначен для личного некоммерческого использования. Для предпросмотра его достаточно; для рабочего сайта, принимающего заказы, выберите план Vercel, разрешающий коммерческое использование, либо другую подходящую площадку.

## Настройка за 10 секунд

Откройте только `src/config/shop.ts` и найдите блок `ЕДИНСТВЕННЫЙ БЛОК НАСТРОЕК ВЛАДЕЛЬЦА`.

1. Укажите цену одной порции в `priceRubles`.
2. Вставьте WhatsApp только цифрами и Telegram без `@`.
3. Отредактируйте `sauces`, `deliveryZones` и `timeSlots` по готовым образцам.
4. После заполнения политики данных поставьте `legalContentReady: true`.
5. Последним действием поставьте `orderingOpen: true`. Для стоп-листа верните `false`.

Если при открытом приёме остались тестовые контакты или не заполнена политика, Zod остановит сборку с понятной ошибкой.

## GitHub → Vercel: 5 шагов

1. Создайте пустой репозиторий на GitHub, распакуйте архив и загрузите в него содержимое папки `bbq-vercel-static`.
2. В GitHub проверьте, что `.env` отсутствует, а `src/config/shop.ts` содержит ваши реальные настройки.
3. Войдите на https://vercel.com через GitHub, нажмите **Add New → Project** и выберите репозиторий.
4. Vercel автоматически определит Next.js. Не добавляйте базу данных и переменные окружения; выберите допустимый для вашего использования план и нажмите **Deploy**.
5. После публикации проверьте расчёт, WhatsApp и Telegram на телефоне. Для своего домена откройте **Project → Settings → Domains**.

## Важное ограничение

В статической версии нет доверенного сервера. Пользователь может изменить JavaScript или текст сообщения, а honeypot останавливает только примитивных ботов. Оператор обязан сверять состав и сумму по `src/config/shop.ts` перед подтверждением заказа. Такая архитектура подходит для заявки в мессенджер, но не для онлайн-оплаты, резервирования остатков или доказательства подлинности заказа.
